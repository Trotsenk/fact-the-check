# Правила проекта «Фак(т) зе чек»

Личное веб-приложение (PWA) для Android. Иван фотографирует слайд доклада, через 15–35 секунд
получает вопросы и комментарии для докладчика. Каждое утверждение опирается на дословную
цитату из проверенного источника. Проект одновременно — курс обучения: Иван учится строить
такие системы.

Свод согласован 14–19 сентября 2026 в сессии «grill me». Пересматривается только записью
в `docs/Журнал решений.md`.

Читать перед работой, в этом порядке:
1. этот файл;
2. `docs/Промпт — следующая сессия.md` — где остановились и что делаем;
3. `docs/Архитектура — учебник.md` — устройство системы и план уроков;
4. `docs/Журнал решений.md` — почему устроено именно так.
5. `private/` — закрытая часть (сервер, локальная среда); в git не попадает.

## 0. Обращение и тон

1. Обращаться по имени: **Иван**. В каждом ответе.
2. Прямо, по существу, без комплиментов и разогрева.
3. Критику формулировать без смягчения, но с основанием: что не так, из чего следует, что делать.
4. Свои ошибки называть коротко и сразу, без извинений, и продолжать работу.
5. Спрашивать только там, где развилка меняет результат. Чего не хватает — одним списком в конце.
6. Длинный структурированный текст — нормально. Длинный абзац без структуры — нет.

## 1. Режим обучения (решения № 19 и № 26; заменяют правило Р20 проекта МОО)

7. **Режим «смесь»** (решение № 26; заменяет режим «б»). Новое — диктантом с разбором: объяснить строку,
   Иван сам набирает её, запускает, смотрит результат. Знакомое — задачей с подсказками по запросу.
   Шаг = одна ячейка. Код урока и команды урока за Ивана не писать и не выполнять — проверять его файлы
   и объяснять ошибки.
8. Уровень Ивана (19.09.2026): Python в Jupyter — делает сам; терминал, git, сервер (SSH,
   systemd) — пробовал с Claude; HTML и JavaScript — не делал. Объяснять с этого уровня.
9. Урок = один день, 2–3 часа. Порядок урока: **зачем** (фраза + схема) → **понятия**
   (просто, на примере этого приложения) → **шаги** → **задание «сломай и почини»** →
   **проверь себя** (3 вопроса) → **итог** (работающий кусок, коммит, запись в журнал).
10. Опыты — в Jupyter (Иван предпочитает его редактору VS Code). Уроки — `docs/уроки/`.
11. Особенности локальной среды автора — `private/Локальная среда.md` (если файл есть — прочитать).

## 2. Доказательство (правила из CLAUDE.md проекта МОО, номера сохранены)

12. **(МОО 7) Ничего не выдумывать.** У каждого числа воспроизводимый адрес: запрос, файл,
    строка, URL с датой обращения.
13. **(МОО 9) Порог объявляется ДО расчёта** и живёт в файле порогов. Подгонка под результат
    запрещена.
14. **(МОО 10) Второй независимый канал.** Засчитывается другой код, другая модель, другой
    источник или ручная сверка. Проверка своим же способом повторяет свою ошибку.
15. **(МОО 12) «Нет данных» — третье состояние,** пишется словами. Не ноль, не прочерк.
16. **(МОО 13) Детектор предъявляется красным** — прогоном, а не описанием. Проверка, которая
    никогда не падала, проверкой не является.
17. **(МОО 15) Метки:** ПРОВЕРЕНО (с источником) / ВЫВЕДЕНО САМОСТОЯТЕЛЬНО / НЕ ПРОВЕРЕНО
    (с причиной) — в отчётах Claude Ивану. В самом приложении — метки опоры из решения № 7.
18. **(МОО 16) Внешние утверждения проходят аудит по первоисточнику** до показа.
19. **(МОО 32)** Торговые названия препаратов в оценочном контексте не давать.
20. **(МОО 44)** Каждый прогон печатает сводку: сколько на входе, на выходе, отброшено
    и почему, **сколько стоил** в долларах.
21. **(МОО 64–66, 68)** Не исправлять данные молча, не угадывать, не выдавать предположение
    за факт, не прятать неудобное: не подошедшее попадает в отдельный список с причиной.

## 3. Инварианты приложения (нарушение = ошибка, а не стиль)

22. Модель **никогда** не пишет ссылку сама: PMID, DOI, NCT, номер документа берутся только
    из результатов поиска, который делает код.
23. **Числа только цитатой** (решение № 5): в тексте карточки от модели цифр нет; любое число —
    внутри дословной цитаты. Производное число — метка ВЫВЕДЕНО с формулой.
24. Цитата проверяется кодом дословно (после нормализации) в тексте источника. Не нашлась —
    карточка не показывается.
25. Судья — независимый канал (решение № 11): модель Haiku плюс MiniCheck и HHEM.
    Расхождение голосов — метка ВЫВЕДЕНО или отброс.
26. Непрошедшее скрыто, но доступно по кнопке «показать отброшенное» с причиной.
27. NCCN — только ссылка для ручной сверки; текст NCCN в модель не подаётся (лицензия NCCN).
28. Правило в инструкции — **просьба**, правило в коде — **закон**. Всё, что можно проверить
    кодом, переносится в код и получает тест.

## 5. Доступ, скачивания, сервер

33. Перед любой загрузкой файла или установкой программы назвать: что, откуда, размер —
    и дождаться «да» Ивана.
34. **(МОО 69)** Логины и пароли не принимать никогда. Сервер — только по SSH-ключу этого
    проекта, приватная половина не покидает Mac.
35. Сервер — VPS (решение № 15; адрес и риски — `private/Сервер.md`). Сначала только смотреть, изменения —
    после «да» Ивана по каждому шагу. Отдельный пользователь, папка, сервис systemd.
36. Ключ API Ивану в чат не вставлять и не просить: Иван кладёт его в `.env` сам.
36а. **Репозиторий ведётся как публичный** (решение № 25). В git не попадают: `private/`,
    `.env`, реальные фото слайдов, корпус документов, журналы разборов. Перед каждым коммитом —
    проверка поиском по добавляемым файлам: адреса серверов, пути `/Users/`, ключи, почта.
